# Zodchi

[English](README.md)

Zodchi — набор рабочих приёмов для Claude Code. В нём настроенные агенты и
процессы (workflows), разложенные по видам работы, и шлюз: через него
процессы зовут модели Codex по **роли**, а не по имени модели.

Это не каркас, который пытается подойти любому проекту. Каждый раздел
содержит агентов и процессы, настроенные под свой вид работы. В `core/`
попадает только то, что действительно одинаково везде.

> **Статус: 1.0 в разработке.** Агенты, процессы и шлюз `zodchi` (на Rust)
> уже работают; следующий шаг — многопользовательский сервер шлюза. Версии 0.x
> в этом репозитории были другим инструментом, они закрыты.

## Что внутри

| Папка | Что в ней |
| --- | --- |
| `core/` | Агенты для всех разделов: `coder`, `runner`, `applier`, `researcher`. Процессы: `code-package`, `ops-script`, `incident-triage` (сообщение пользователя об ошибке — в черновик ответа или задания на исправление, см. [docs/incident-triage.md](docs/incident-triage.md)) |
| `domains/web-apps/` | Веб-приложения: `branch-review` перед выпуском |
| `domains/gamedev-unity/` | Ассеты игры в Blender и Unity: `asset-round`, `method-question`, `rubric-probe`, `unity-check`, агенты `modeller`, `unity-runner`, `art-critic` |
| `models.json` | Таблица ролей: какая модель играет какую роль, по порядку предпочтения |
| `roles/` | Роли шлюза: `code-review`, `checkout-review`, `architecture-review`, `code-patch`, `package-work`, `research`, `text`, `image`, `art-critic`, `decisions` |
| `.claude-plugin/` | Маркетплейс: каждая из папок `core/` и `domains/*` — плагин Claude Code |
| `install/` | Установщик и команда `zodchi` |
| `gateway/` | Шлюз `zodchi` на Rust: зовёт модели Codex по ролям на ваших собственных подписках |
| `docs/` | Как всё устроено, подписки, форк для компании |

## На чём это держится

- **Процессы зовут роли, а не модели.** Кто пишет, ревьюит и запускает,
  зависит от лимитов ваших подписок, а лимиты меняются. В `models.json` у
  каждой роли — список кандидатов по порядку. Первый шаг процесса берёт
  первого кандидата, у которого остался лимит, и сообщает, если пришлось
  переключиться.
- **Ревьюер никогда не автор.** Код модели Claude ревьюит модель Codex через
  шлюз, и наоборот.
- **Процессы останавливаются.** У `code-package` три круга ревью. Если
  одобрения нет, процесс останавливается и возвращает вопрос вам, а не
  ходит по кругу.
- **Черновую работу делают дешёвые модели.** Проверки, применение готового
  патча и поиск — дело Haiku. Дорогие модели остаются для решений, от
  которых зависит всё остальное.
- **Один пакет на файл.** `code-package` не стартует, если другой открытый
  пакет уже занял один из его файлов: конфликтов при rebase не будет.
- **Ничего не запускается под sudo без пробного прогона.** `ops-script`
  проверяет скрипт и гоняет его без root на копии, и только потом у вас
  спрашивают пароль. Файлы, которые скрипту нужны рядом, передаются в
  `files`; команду вы получаете для своего терминала (`ssh -t` для сервера),
  потому что у `!` в Claude Code нет TTY для пароля sudo.
  [docs/patterns.md](docs/patterns.md) описывает устройство такого скрипта
  («A script a human runs with sudo»).

## Установка

Нужны [Claude Code](https://code.claude.com) и Node.js 20 или новее. Для
шлюза ещё нужен [Rust](https://rustup.rs), чтобы его собрать, и
[Codex CLI](https://learn.chatgpt.com/docs), вошедший в вашу собственную
подписку ChatGPT.

```sh
git clone https://github.com/Inkasor/zodchi.git
cd zodchi
./install/install.sh                    # macOS, Linux
.\install\install.ps1                   # Windows PowerShell
```

Установщик включит `zodchi-core` для вас во всех проектах, соберёт шлюз
(если стоит Rust) и положит таблицу ролей и роли шлюза в `~/.zodchi`.
Разделы включаются по проектам:

```sh
./install/install.sh --project ~/code/my-game --domains gamedev-unity
```

- Агенты и процессы приходят как плагины Claude Code из этого репозитория
  (маркетплейс `zodchi`): `zodchi-core`, `zodchi-web-apps`,
  `zodchi-gamedev-unity`. Ядро включено во всех проектах; раздел — только в
  тех, что вы назвали, и только для вас (он ложится в
  `.claude/settings.local.json` проекта, который не коммитится). `--domains`
  без `--project` включает раздел везде.
- Плагины читаются из копии, а не из вашего клона. Установщик копирует файлы
  плагинов в `~/.zodchi/plugins/<коммит>/` и регистрирует эту папку как
  маркетплейс, поэтому смена ветки или правка файлов в клоне ничего не
  меняют для сессий Claude Code на вашей машине. Он откажется копировать из
  ветки, которая не основная, и из дерева с неснятыми правками отслеживаемых
  файлов (`--force` скопирует всё равно; суффикс `<коммит>-dirty` дают только
  правки отслеживаемых файлов, чистая ветка с `--force` называется просто по
  коммиту). После
  `git pull` перезапустите установщик: он сделает новую копию, переключит на
  неё маркетплейс, обновит плагины и пересоберёт шлюз. Предыдущая копия
  остаётся для сессии, которая ещё ею пользуется; копии старше двух
  последних удаляются (копия, из которой маркетплейс читал до этого запуска,
  тоже остаётся, даже если она старше, так что копий может быть три). Установка прежней версии, которая читала сам клон,
  при следующем запуске переезжает в копию.
- `--dev` нужен для работы над самим zodchi: маркетплейсом остаётся клон,
  как раньше. Тогда каждая сессия Claude Code на машине, которая стартует или
  перечитывает плагины, видит рабочее дерево клона как оно есть, в том числе
  недоделанную ветку; включайте его только пока разрабатываете zodchi и
  потом перезапустите установщик без `--dev`, чтобы вернуться на копию.
- Процессы запускаются как `/zodchi-core:code-package`,
  `/zodchi-gamedev-unity:asset-round` и так далее, а агенты называются
  `zodchi-core:runner` и подобно, поэтому не пересекаются со своими агентами
  проекта.
- Если Rust установлен, установщик сам соберёт шлюз (`--no-build` это
  пропускает). Свои подписки перечислите в `~/.zodchi/accounts.json`, см.
  [gateway/README.md](gateway/README.md).
- Установщик не перезаписывает файл, который положил не он или который вы
  изменили. `~/.zodchi/models.json` после первой установки ваш: новая
  таблица ляжет рядом, как `models.json.new`.
- `--dry-run` показывает, что изменится. `--uninstall` убирает поставленное и
  оставляет ваши правки. Если поставлено с копии (по умолчанию), убираются
  регистрация маркетплейса и копии плагинов, а вместе с маркетплейсом Claude
  Code убирает все плагины, поставленные из него: zodchi-core и доменные
  плагины, включённые в других проектах. После `--dev` маркетплейс — сам
  клон: удаление убирает только zodchi-core, а маркетплейс и доменные плагины
  остаются (установщик напечатает, как их убрать). С `--no-plugins` плагины
  Claude Code, маркетплейс и копии не трогаются.

Потом запускайте процесс из Claude Code, например `/zodchi-core:code-package`,
или попросите Claude запустить его с вашими аргументами. Аргументы каждого
процесса описаны в его заголовке.

## Ваши модели

Поправьте `~/.zodchi/models.json` под свои подписки. Репозиторий может
переопределить роли в `.zodchi/models.json`, а отдельный запуск — в своих
аргументах (`models`). Кандидат `claude` работает как субагент Claude Code,
кандидат `codex` — через шлюз на вашем входе в Codex.

## Подписки: что разрешено

Каждый пользуется **своей** подпиской. Условия OpenAI запрещают обслуживать
одной подпиской ChatGPT нескольких людей, будь то через общий вход или через
сервер. Запрещена и ротация аккаунтов в обход лимитов. Zodchi не
поддерживает ни то, ни другое. Подробности и источники —
в [docs/subscriptions.md](docs/subscriptions.md).

## Форк для компании
