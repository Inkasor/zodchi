# Zodchi

[English](README.md)

Zodchi запускает общие рабочие процессы для Codex и Claude Code. Движок на Rust готовит контекст, вызывает модели по ролям, выполняет ваши проверки и записывает каждый шаг в журнал. Прерванный запуск продолжается с места остановки, его может подхватить и другой клиент. Правила — кто пишет, кто проверяет, какие проверки обязаны пройти, что может блокировать ревью — соблюдает программа, а не промпт.

## Зачем Зодчи

- **Правила держит программа, а не промпт.** Писатель никогда не проверяет своё изменение сам, ваши проверки обязаны пройти до ревью, а заявка не даёт двум запускам править одни файлы. Агент не может уговорить программу их обойти. Рецензента просят соблюдать границы ревью из брифа и правила `REVIEW.md` репозитория.
- **Прерванная работа продолжается.** Каждый вызов модели, проверка и коммит записываются в журнал. Оборванный запуск продолжается с последнего шага, в том же или другом клиенте, и не платит второй раз за сделанный шаг.
- **Дешевле в замере одного из первых пользователей.** Небольшое изменение стоило $0.21 вместо $1.05 и заняло 6 минут вместо 20. Большое — $2.98 вместо $4.03, примерно за то же время.

## Быстрый старт

1. Установите Зодчи (см. выше) и начните новый чат в своём проекте.
2. Скажите агенту: **«Сделай это пакетом Зодчи: <нужное изменение>. Сначала покажи пробный запуск.»**
3. Агент напишет бриф и файл аргументов и покажет `--dry-run`: какие модели, какие файлы, какие проверки. Ничего при этом не отправляется и не заявляется. Потом он запустит пакет на переднем плане:

```sh
zodchi flow code-package --args package.json --dry-run
zodchi flow code-package --args package.json
```

Чтобы запустить пакет в фоне самому, добавьте `--detach` и ждите через `zodchi flow wait <run-id>`.

```json
{
  "label": "export-csv",
  "brief": "/abs/path/repo/.agent-tmp/flow/export-csv-brief.md",
  "repo": "/abs/path/repo",
  "files": ["src/export.mjs", "test/export.test.mjs"],
  "checks": ["npm ci", "node test/export.test.mjs"]
}
```

Модель-писатель вносит изменение, движок запускает ваши проверки и коммитит раунд в вашу ветку, а независимая модель проверяет результат по брифу. С `"isolated": true` изменение остаётся на ссылке-кандидате до одобрения, и его вносит `zodchi flow apply <run-id>`. Все аргументы — в [Code package](docs/flow.md), а работу, которой нужно несколько пакетов, — см. [Большая работа пакетами](docs/large-work.md).

Примеры запросов:
- *«Добавь выгрузку CSV на страницу отчёта пакетом Зодчи; заяви экспортёр и его тест».*
- *«Проверь мою ветку против main через Зодчи branch-review с нашими тестами».*
- *«Преврати эту цель в бриф Зодчи (design-brief) и разбей на пакеты».*

Повседневные команды:

```sh
zodchi flow runs --active                    # живые запуски
zodchi flow wait <run-id>                    # ждать, пока запуск закончится или понадобитесь вы (или --all)
zodchi flow status <run-id>                  # один запуск подробно
zodchi flow close <run-id> --reason "..."    # закрыть ждущий или остановленный запуск, без шага модели
zodchi flow cancel <run-id> --reason "..."   # остановить живой запуск, без шага модели
zodchi flow verify <commit>                  # проверки проекта на коммите, без модели
```

Агенты могут задать `ZODCHI_AGENT=1`, чтобы получать ошибки в stderr в виде JSON, а `zodchi --usage` печатает в JSON все команды, флаги, переменные и настройки. Коды выхода `zodchi flow`: 0 — успех, одобрено или закрыто владельцем; 1 — неверный вызов или сбой команды; 2 — отказ, остановка или не одобрено. В режиме агента 3 значит «нужен вход»; у `flow wait` 3 значит ещё и истёкшее ожидание (`status: timeout`).

**Закрепляйте версию в CI.** В CI и на общих машинах ставьте конкретный выпуск ([инструкция по установке](docs/install.ru.md)). Версии процессов записываются в каждый журнал, но плавающая установка меняет промпты и проверки у вас под ногами.

## Рабочие процессы

Команда `zodchi flow list` показывает процессы, доступные в проекте, а `zodchi flow <процесс> --help` — подробности одного из них. [Старт и продолжение запуска](docs/flow.md#running-it) устроены одинаково в Codex и Claude Code.

| Задача | Руководство |
| --- | --- |
| Превратить цель в проверенный бриф или план пакетов | [Design brief](docs/design-brief.md) |
| Внести и проверить изменение кода | [Code package](docs/flow.md) |
| Провести большую работу серией пакетов | [Большая работа](docs/large-work.md) |
| Проверить готовую ветку вместе с тестами | [Branch review](docs/flow.md#branch-review) |
| Проверить веб-приложение или игровой билд | [Приёмка](docs/acceptance.md) |
| Исследовать вопрос по своим материалам | [Research](docs/research.md) |
| Подготовить и проверить видео | [Видео](docs/flow-video.md) |
| Озвучить реплики и выгрузить дорожку дубляжа | [Озвучка](docs/voiceover.md) |
| Загрузить одобренное видео приватно | [YouTube](docs/youtube-publish.md) |
| Убрать остатки завершённых запусков | [Уборка](docs/cleanup.md) |

Остальные процессы — в [общем каталоге](workflows/catalog.json). Модели для них выбираются в [таблице ролей](docs/model-roles.md): по умолчанию это модели Codex; модели Claude можно включить для разовых ролей ([роли Claude](docs/flow-claude.md)).

## Какие данные уходят какой модели

Зодчи работает на вашем компьютере. Журнал, Git, проверки и коммиты остаются локально; наружу уходят только шаги моделей и только тем путём, который вы настроили:

| Путь | Когда | Куда |
| --- | --- | --- |
| Локальный шлюз Codex | модель `codex`, сервер не настроен (по умолчанию) | OpenAI, под вашим входом в Codex. С `"credits": true` в `~/.zodchi/flow.json` шаги могут тратить кредиты ChatGPT, когда лимит подписки исчерпан; `flow status` показывает расход каждого шага |
| Сервер компании | модель `codex` и `server` в `~/.zodchi/flow.json` | zodchi-server вашей организации, он вызывает модель; журнал и Git остаются локально ([сервер](docs/flow-server.md)) |
| Claude Code CLI | модель `claude`, только если в вашем `~/.zodchi/flow.json` есть `"claude": true` | Anthropic, по вашей подписке Claude; в вызове нет инструментов, MCP, хуков и CLAUDE.md |
| OpenAI Decisions API | только `rubric-probe` | OpenAI, с вашим платным ключом API |

Что отправляет каждый процесс:

| Процесс | Что уходит модели |
| --- | --- |
| code-package | бриф и полный текст заявленных файлов после проверки входа; ревьюер получает diff, бриф, эти файлы и `REVIEW.md`; хвосты логов проверок без строк с ключами и без путей машины |
| branch-review | diff и файлы контекста, построчно очищенные от приватных слов и ключей |
| design-brief | цель и переданные документы, `AGENTS.md`/`CLAUDE.md` и полный текст файлов из `questions` (`.env*`, ключи и файлы учётных данных исключаются) |
| research | только запрос, файлы вопросов, до 12 вложений и прежние решения — ни репозитория, ни интернета |
| incident-triage | отчёт об инциденте и разрешённые вами ограниченные чтения, с вычисткой |
| приёмка | ничего, если не просить отбор сценариев (`choose`) или оценку кадров (`review`); тогда критерий и снятые кадры |
| ops-script | ничего, пока не нужен ремонт; тогда дочерний code-package со скриптом |
| проверки, `flow verify`, уборка, workspace-audit | ничего — они работают локально без модели |

Фильтр. Слова, которые не должны попасть к модели (названия компании, клиентов, продуктов), запишите по одному в строке в `~/.zodchi/private-words.txt` (или в файл из `ZODCHI_DENYLIST`). Строки с такими словами, со значениями ключей или внутри блока закрытого ключа заменяются до сборки промпта, одинаково для любого пути — в research, branch-review, design-brief, incident-triage, ремарках и контексте ревью. code-package проверяет бриф и заявленные файлы до заявки и до вызова модели. Если в файле есть приватный материал, он отказывает и называет файл и строку, но не сам текст. Если вы убедились, что найденная строка не секрет (например, тестовая фикстура), перечислите её в `allowInputLines`. В режиме агента писатель работает в копии репозитория, которая не фильтруется, и результат об этом сообщает. Research без файла приватных слов не запускается, пока вы явно это не разрешите.

Всё, что хранит Зодчи — журналы с полными промптами, копии писателей, кандидаты, папки проверок, — лежит в `~/.zodchi` (или `ZODCHI_HOME`) и в игнорируемой папке репозитория `.agent-tmp/`. Журналы никуда не выгружаются. Что и когда удаляется — см. [Уборка](docs/cleanup.md).
