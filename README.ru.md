# Zodchi

[English](README.md)

Zodchi — набор рабочих приёмов для Claude Code. В нём настроенные агенты и
процессы (workflows), разложенные по видам работы, и шлюз: через него
процессы зовут модели Codex по **роли**, а не по имени модели.

Это не каркас, который пытается подойти любому проекту. Каждый раздел
содержит агентов и процессы, настроенные под свой вид работы. В `core/`
попадает только то, что действительно одинаково везде.

> **Статус: 1.0 в разработке.** Агенты, процессы и шлюз `zodchi` (на Rust)
> уже работают; следующий шаг — многопользовательский сервер шлюза. Версии 0.x
> в этом репозитории были другим инструментом, они закрыты.

## Что внутри

| Папка | Что в ней |
| --- | --- |
| `core/` | Агенты для всех разделов: `coder`, `runner`, `applier`, `researcher`. Процессы: `code-package`, `ops-script`, `incident-triage` (сообщение пользователя об ошибке — в черновик ответа или задания на исправление, см. [docs/incident-triage.md](docs/incident-triage.md)), `design-brief` (от цели к заданию, которое может выполнить `code-package`: факты только чтением, черновик, независимая проверка через шлюз, одна правка, см. [docs/design-brief.md](docs/design-brief.md)). Навыки: `workspace-audit` (разбор захламлённой папки: исследователи только читают, решения одной пачкой, потом один исполнитель) и `zodchi-flow` (выполнить задачу кода через `zodchi flow code-package` из сессии Claude Code) |
| `codex/` | Навык Codex `zodchi-flow`: то же, из сессии Codex (см. [Три способа запустить пакет](#три-способа-запустить-пакет)) |
| `domains/web-apps/` | Веб-приложения: `branch-review` перед выпуском |
| `domains/gamedev-unity/` | Ассеты игры в Blender и Unity: `asset-round`, `method-question`, `rubric-probe`, `unity-check`, агенты `modeller`, `unity-runner`, `art-critic` |
| `models.json` | Таблица ролей: какая модель играет какую роль, по порядку предпочтения |
| `roles/` | Роли шлюза: `code-review`, `checkout-review`, `architecture-review`, `code-patch`, `package-work`, `research`, `text`, `image`, `art-critic`, `decisions` |
| `.claude-plugin/` | Маркетплейс: каждая из папок `core/` и `domains/*` — плагин Claude Code |
| `install/` | Установщик и команда `zodchi` |
| `gateway/` | Шлюз `zodchi` на Rust: зовёт модели Codex по ролям на ваших собственных подписках |
| `docs/` | Как всё устроено, подписки, форк для компании |

## На чём это держится

- **Процессы зовут роли, а не модели.** Кто пишет, ревьюит и запускает,
  зависит от лимитов ваших подписок, а лимиты меняются. В `models.json` у
  каждой роли — список кандидатов по порядку. Первый шаг процесса берёт
  первого кандидата, у которого остался лимит, и сообщает, если пришлось
  переключиться.
- **Ревьюер никогда не автор.** Код модели Claude ревьюит модель Codex через
  шлюз, и наоборот.
- **Процессы останавливаются.** У `code-package` три круга ревью. Если
  одобрения нет, процесс останавливается и возвращает вопрос вам, а не
  ходит по кругу.
- **Сначала запуск, потом ревью.** `code-package` запускает проверку репозитория, останавливается, если изменение правит существующий тест, записывает в коммит, как он проверен, и ревьюит по `REVIEW.md` репозитория, см. [docs/verification.md](docs/verification.md).
- **Ревью останавливается там, где говорит задание.** Раздел `## Review boundary` задания цитируется ревьюеру, а круг, который лишь уходит вглубь, завершает запуск: новые замечания отдаются на разбор вместе с предложенными строками для `REVIEW.md`, см. [docs/review-boundary.md](docs/review-boundary.md). Несколько пакетов могут делить одну копию репозитория или работать в worktree и клонах, см. [docs/parallel.md](docs/parallel.md).
- **Процессы как код, без Claude Code.** `zodchi flow code-package` проводит тот же цикл пакета в самом шлюзе, только на Codex: писатель без оболочки отвечает патчем, движок применяет его, проверяет, коммитит и записывает каждый шаг в журнал, так что прерванный запуск продолжается, см. [docs/flow.md](docs/flow.md).
- **Черновую работу делают дешёвые модели.** Проверки, применение готового
  патча и поиск — дело Haiku. Дорогие модели остаются для решений, от
  которых зависит всё остальное.
- **Один пакет на файл.** `code-package` не стартует, если другой открытый
  пакет уже занял один из его файлов: конфликтов при rebase не будет.
- **Ничего не запускается под sudo без пробного прогона.** `ops-script`
  проверяет скрипт и гоняет его без root на копии, и только потом у вас
  спрашивают пароль. Файлы, которые скрипту нужны рядом, передаются в
  `files`; команду вы получаете для своего терминала (`ssh -t` для сервера),
  потому что у `!` в Claude Code нет TTY для пароля sudo.
  [docs/patterns.md](docs/patterns.md) описывает устройство такого скрипта
  («A script a human runs with sudo»).

## Установка

Нужны [Claude Code](https://code.claude.com) и Node.js 20 или новее. Для
шлюза ещё нужен [Rust](https://rustup.rs), чтобы его собрать, и
[Codex CLI](https://learn.chatgpt.com/docs), вошедший в вашу собственную
подписку ChatGPT.

```sh
git clone https://github.com/Inkasor/zodchi.git
cd zodchi
./install/install.sh                    # macOS, Linux
.\install\install.ps1                   # Windows PowerShell
```

Установщик включит `zodchi-core` для вас во всех проектах, соберёт шлюз
(если стоит Rust) и положит таблицу ролей и роли шлюза в `~/.zodchi`.
Разделы включаются по проектам:

```sh
./install/install.sh --project ~/code/my-game --domains gamedev-unity
```

- Агенты и процессы приходят как плагины Claude Code из этого репозитория
  (маркетплейс `zodchi`): `zodchi-core`, `zodchi-web-apps`,
  `zodchi-gamedev-unity`. Ядро включено во всех проектах; раздел — только в
  тех, что вы назвали, и только для вас (он ложится в
  `.claude/settings.local.json` проекта, который не коммитится). `--domains`
  без `--project` включает раздел везде.
- Плагины читаются из копии, а не из вашего клона. Установщик берёт коммит,
  на который указывает HEAD клона, и git записывает файлы плагинов этого
  коммита (`.claude-plugin`, `core`, `domains`) в
  `~/.zodchi/plugins/<хеш коммита>/`; эта папка регистрируется как
  маркетплейс. Копия делается только из коммита, никогда из рабочего дерева:
  неснятые правки в неё не попадают (установщик скажет об этом одной
  строкой), а смена ветки или правка файлов в клоне ничего не меняют для
  сессий Claude Code на вашей машине. Он откажется копировать из ветки,
  которая не основная (та, на которую указывает `refs/remotes/origin/HEAD`),
  из отсоединённого HEAD и когда основная ветка не задана (её задаёт
  `git remote set-head origin --auto`); `--force` скопирует коммит всё
  равно. Папку, которая не клон git, он не возьмёт без `--dev`. Копия
  пишется под временным именем, каждый файл сверяется со своим объектом в
  коммите, последней копия получает отметку `.complete` и только потом
  переименовывается; папка копии без этой отметки или без какого-то файла
  убирается в сторону и делается заново. После `git pull` перезапустите
  установщик: он сделает новую копию, переключит на неё маркетплейс, обновит
  `zodchi-core` и разделы, названные в этом запуске, и пересоберёт шлюз.
  Раздел, включённый раньше в другом проекте, этот запуск не обновляет:
  перезапустите установщик с `--project <тот репозиторий> --domains <раздел>`
  для каждого такого проекта. Остаются копия, из которой читает маркетплейс,
  та, из которой он читал до неё, две самые новые полные копии и все копии
  моложе семи дней (открытая сессия Claude Code продолжает читать ту копию,
  с которой начала); более старые удаляются. После переключения установщик перечитывает регистрацию
  маркетплейса и печатает, куда она указывает; если переключить не удалось,
  он печатает, что зарегистрировано сейчас, а новая копия остаётся рядом.
  Установка идёт по одной за раз (`~/.zodchi/plugins/.install.lock`;
  блокировку процесса, которого уже нет, следующий запуск забирает). Установка
  прежней версии, которая читала сам клон, при следующем запуске переезжает
  в копию. Установщик рассчитан на одного человека на своей машине: блокировка
  защищает копии плагинов и маркетплейс, а не каждый файл установщика, и два
  установщика, запущенные в одно мгновение, ещё могут столкнуться на старой блокировке.
- `--dev` нужен для работы над самим zodchi: маркетплейсом остаётся клон,
  как раньше. Тогда каждая сессия Claude Code на машине, которая стартует или
  перечитывает плагины, видит рабочее дерево клона как оно есть, в том числе
  недоделанную ветку; включайте его только пока разрабатываете zodchi и
  потом перезапустите установщик без `--dev`, чтобы вернуться на копию.
- Процессы запускаются как `/zodchi-core:code-package`,
  `/zodchi-gamedev-unity:asset-round` и так далее, а агенты называются
  `zodchi-core:runner` и подобно, поэтому не пересекаются со своими агентами
  проекта.
- Если Rust установлен, установщик сам соберёт шлюз (`--no-build` это
  пропускает). Свои подписки перечислите в `~/.zodchi/accounts.json`, см.
  [gateway/README.md](gateway/README.md).
- Установщик не перезаписывает файл, который положил не он или который вы
  изменили. `~/.zodchi/models.json` после первой установки ваш: новая
  таблица ляжет рядом, как `models.json.new`.
- Навык Codex `zodchi-flow` (`codex/skills/`) ставится в папку навыков Codex,
  `$CODEX_HOME/skills` или `~/.codex/skills`, как управляемый файл наравне с
  остальными: файл с таким именем, который положил не установщик или который
  вы изменили, не трогается (`--force` заменяет его), а `--uninstall` его
  убирает. `--no-codex-skill` не трогает ни навык, ни его прежнюю копию. Навык
  Claude Code с тем же именем входит в плагин `zodchi-core` и приходит вместе
  с ним.
- `--dry-run` показывает, что изменится. `--uninstall` убирает поставленное и
  оставляет ваши правки. Если поставлено с копии (по умолчанию), убираются
  регистрация маркетплейса и копии плагинов, а вместе с маркетплейсом Claude
  Code убирает все плагины, поставленные из него: zodchi-core и доменные
  плагины, включённые в других проектах. После `--dev` маркетплейс — сам
  клон: удаление убирает только zodchi-core, а маркетплейс и доменные плагины
  остаются (установщик напечатает, как их убрать). С `--no-plugins` плагины
  Claude Code, маркетплейс и копии не трогаются.

Потом запускайте процесс из Claude Code, например `/zodchi-core:code-package`,
или попросите Claude запустить его с вашими аргументами. Аргументы каждого
процесса описаны в его заголовке.

## Ваши модели

Поправьте `~/.zodchi/models.json` под свои подписки. Репозиторий может
переопределить роли в `.zodchi/models.json`, а отдельный запуск — в своих
аргументах (`models`). Кандидат `claude` работает как субагент Claude Code,
кандидат `codex` — через шлюз на вашем входе в Codex.

## Три способа запустить пакет

`zodchi flow code-package` (см. [docs/flow.md](docs/flow.md)) проводит пакет кода как код в шлюзе. Запустить его можно
тремя способами; движок, журнал и результат везде одни и те же. Навык `zodchi-flow` говорит агенту, как: превратить
задачу в задание и файл аргументов, запустить `zodchi flow code-package --args <файл>` на переднем плане, прочитать
JSON результата, продолжить прерванный запуск через `--resume <run-id>` и отчитаться. Он не правит журнал, не
отправляет шаги вручную заново и не переключает ветки во время запуска.

| Способ | Кто запускает | Кто отвечает на шаги моделей | Настройка |
| --- | --- | --- | --- |
| 1. Из сессии Codex (сначала Codex) | навык Codex `zodchi-flow` | Codex на вашем входе или сервер вашей компании | установщик кладёт навык в `~/.codex/skills`; для сервера — `flow.json` ниже |
| 2. Из сессии Codex с ролями Claude | тот же навык | писатель Claude через Claude Code CLI на вашей машине, ревьюер Codex | `"claude": true` в `flow.json` и кандидат Claude первым у `expertWriter` в `models.json` |
| 3. Из сессии Claude Code (сначала Claude) | навык Claude Code `zodchi-flow` из `zodchi-core` | как в 1 или 2, что настроили | установщик ставит плагин |

Сторону моделей каждый настраивает в своём `~/.zodchi/flow.json` (`$ZODCHI_HOME/flow.json`); без файла шаги моделей
идут в локальный шлюз на вашем входе в Codex, как в способе 1.

Через сервер компании (коллега без входа в Codex; см. [docs/flow-server.md](docs/flow-server.md)):

```json
{ "server": "https://zodchi.example.org", "tokenFile": "~/.zodchi/flow-token" }
```

С ролями Claude (см. [docs/flow-claude.md](docs/flow-claude.md)) — `flow.json` и `models.json`:

```json
{ "claude": true }
```

```json
{ "version": 1, "roles": {
  "expertWriter": { "candidates": [{ "provider": "claude", "model": "opus", "effort": "high" }, { "provider": "codex", "model": "gpt-6.2-sol", "effort": "medium" }] },
  "reviewer": { "candidates": [{ "provider": "codex", "model": "gpt-6.2-sol", "effort": "medium" }] }
} }
```

## Подписки: что разрешено

Каждый пользуется **своей** подпиской. Условия OpenAI запрещают обслуживать
одной подпиской ChatGPT нескольких людей, будь то через общий вход или через
сервер. Запрещена и ротация аккаунтов в обход лимитов. Zodchi не
поддерживает ни то, ни другое. Подробности и источники —
в [docs/subscriptions.md](docs/subscriptions.md).
